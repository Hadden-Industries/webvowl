# Dependency graphs and affected Jest tests

These opt-in developer commands use the installed dependency-cruiser and Jest.
Ordinary `npm test`, `npm run check`, specialized architecture suites and hosted checks keep their independent scope.
A full Jest result is not full product assurance: Python, Markdown, build, browser and external corpus obligations remain separate.

## Choose a command

| Task                                                   | Command                                                                                                 |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| Export the graph to a new external directory           | `npm run graph:dependencies -- --output C:/new-external-directory/webvowl-graph`                        |
| Follow a literal file or artifact to its consumers     | `npm run graph:dependencies -- --output C:/new-external-directory/webvowl-graph --focus src/example.js` |
| List affected files without running tests              | `npm run check:affected -- --base <full-commit-object-id> --list`                                       |
| Widen that list with a literal path                    | `npm run check:affected -- --base <full-commit-object-id> --path src/example.js --list`                 |
| Compare the selected run with the full suite           | `npm run check:affected -- --base <full-commit-object-id> --shadow`                                     |
| Run the full current Jest inventory without a baseline | `npm run check:affected`                                                                                |

## Read the graph bundle

Graph output requires a new external directory.
Existing destinations and linked parents are refused.
The command reserves the requested directory exclusively, prepares its contents privately, then atomically publishes the complete `bundle/` subdirectory.
That bundle contains `dependencies.json`, the typed graph used for test selection, and `graph.json`, the original dependency-cruiser result.
Native policy findings, the reviewed policy bytes and the Node-context Mermaid views remain available in the bundle.

Use the typed digest in `provenance.json` to compare the typed export, a focus report and the matching candidate in a list report.
The Mermaid views bind the native graph digest.
An interrupted reservation without `bundle/provenance.json` is incomplete; retain its `.incomplete-*` diagnostics.
The exporter returns nonzero for unresolved native policy errors.
The five browser-root imports exercised by WebVOWL's Vite qualification utilities carry browser-context witnesses alongside their original Node findings.
A matching Node use or missing Vite target keeps the error blocking.

In the typed graph an edge points from the dependent to its input.
For example, a reader points to a generated file, and a generated file points to its producer.
Focus follows incoming edges and reports direct and transitive consumers and a deterministic shortest path to each.
Edges identify where they were observed or declared.
Unresolved file readers, processes and workflow expressions appear in `resourceDiagnostics`.
Vite copy edges identify potential production destinations.
Actual generated bytes and plugin filters are checked by the build and its owned-asset manifest.

The complete graph includes disconnected authored application, utility, workspace, conformance and test modules.
Installed vendor internals are leaves.
Each source snapshot resolves `vowl` through its own package exports before installed vendor directories.

Historical source is read from Git blobs into an owned temporary directory.
Historical code, config, hooks and dependency installations never run.
JavaScript, package manifests, the HTML entry and workflow metadata retain exact blob bytes.
Other authored resources can be resolution leaves.
Base and candidate traversal run independently before the current test paths are unioned.

## Select a baseline and interpret fallback

Supply an immutable full commit ID representing the entire intended comparison.
Intermediate implementation commits do not authorize moving that comparison forward.
Selection unions committed, staged, unstaged and untracked changes; renames retain both endpoints and staged intent survives a later working-file revert.
Additional `--path` arguments only widen that envelope.
Paths are literal, including spaces, Unicode and regular-expression punctuation.

`--list` independently discovers the full current Jest inventory and runs no test modules.
The report explains each selected whole file with a direct change, a path through one snapshot, or a diagnostic from a possible consumer.
The first narrower resource class covers supported files in test fixture directories with a source-backed Jest reader.
The selector also includes tests that can reach an unchanged reader or launcher whose input is unresolved.
Review the relevant diagnostics and listed independent commands before running checks.

A missing/invalid baseline, incompatible policy or controls, unobserved intermediate index state, an unproved resource, deleted tests, uncertain loading boundary, unknown root, blocking graph findings, no changes or empty reachability uses full current inventory.
Unsafe inventory, configuration, path or candidate drift fails nonzero.
A baseline predating this feature normally falls back because its policy differs.

Execution uses Jest's native JSON configuration, VM module flags, two-worker default and exact whole-file paths.
Arbitrary forwarded Jest options are not accepted.

The repository's selected Python environment supplies a small native containment adapter: Windows uses a non-breakaway job assigned before the suspended Jest process starts; Linux uses a private child subreaper and pidfds.
Unsupported or unavailable containment fails before a successful result can be reported.
This helper does not substitute for repository Python qualification.

## Compare and retain test results

Shadow mode discovers full inventory again independently, runs selected files, then runs the full inventory and compares outcomes for the selected files.
Any full failure, selected failure, missing result or disagreement remains nonzero.
Duplicate assertion names retain ordered multiplicity, and skips/todos remain distinct.
When the selection is already full, one full execution is honestly reported as fallback; there is no fabricated second-run agreement.

Selective execution supports Windows and Linux with the selected repository Python environment.
Platform containment probes run in the existing Python matrix, including an actual native ESM Jest run.
The Linux Python job also runs the selected/shadow JavaScript adapter regressions with its selected environment.

Use shadow mode to qualify unfamiliar changes and retain any disagreement as a failed result.
Ordinary full Jest is the immediate recovery route.

Runtime results retain raw stdout/stderr, Jest JSON, native process facts, selected paths, outcome comparison and timings in the reported external result directory.
Pass `--output <new absolute external directory>` to retain an execution under an owned Work directory.
Timing fields distinguish initial discovery, remaining planning, execution rediscovery, selected execution, full execution and total planning plus execution cost.
An incomplete execution still writes a failed report when its reserved output directory remains writable.

They are operator provenance, not authenticated GitHub evidence or HISEW receipts.
Keep failed runs and incomplete cleanup evidence until their consumers release them.
Do not overwrite an earlier bundle or delete a shared temporary/evidence root.
Candidate content, index and HEAD are checked for drift around the operation; changed inputs require a fresh run.

Initial limits are 8,192 repository records, 4,096 authored modules, 8 MiB per source, 64 MiB materialized source, 16 MiB graph output, a 30-second analyzer deadline with a 256 MiB V8 old-space limit, 120-second discovery, 600-second test execution, 64 MiB combined result/stream capture, and five seconds for cleanup.

The V8 heap limit is not a native RSS limit.
Exceeding a bound never yields a truncated successful result.
Windows command-line capacity can impose a smaller whole-file execution bound; a native launch rejection remains a failed, incomplete run.
Measure selection, execution and total cost against an independent full run; selected-file count alone is not a speedup claim.

The impact registry in `.test-impact.json` is a reviewed completeness boundary.
Supported literal file reads and worker launches are observed automatically.
Review new computed loads, generated programs and unresolved relationships for a source-backed declaration or wider verification.
Do not add a broad exception to improve timing.
Preserve the existing specialized architecture assertions as independent oracles.

## Use the report during HISEW verification

Use the execution's accepted comparison commit for `npm run check:affected -- --base <full-commit> --list`.
Review the changed behavior, the affected assertion and its graph path, and any independent checks.
Use `hisew verify-change-execution --selection affected --list-only` to preview native obligations.
Supply independently required discovered test files with `--additional-path` where supported.
When the installed engine needs a full scope, preview and use `--selection all` through its native admission.
Local selected or shadow results remain operator evidence.
Native invocation and retained verdicts supply HISEW receipts.

## Prepare graph tool versions

Run `node util/graph-toolchain-versions.mjs` to compare the pinned and installed toolchain with the public stable npm tags and Node LTS.
The read-only report shows exact release identities, dependency requirements and registry or installation gaps.
After approval of an exact lockfile delta, use the selected npm in the preparation workspace with lifecycle scripts disabled.
Inspect the generated delta before incorporating it and freeze the approved lock with `npm ci --ignore-scripts` before verification.
